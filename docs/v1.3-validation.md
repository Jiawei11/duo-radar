# v1.3.0 validation

Windows x64, local Chrome, 2026-10-17 (America/Chicago).

The opt-in `live_us_cart_and_repeat` test used an initially empty profile for each monitor and iPhone 17 256GB Mist Blue (MG484LL/A).

| Monitor | Applied ZIP | Verified result |
| --- | --- | --- |
| R144 · NorthPark Center | 75225 | Guest pickup results contained R144 |
| R095 · Fifth Avenue | 10153 | A separate guest cart returned New York stores including R095 |

Both flows verified the exact SKU and quantity 1 before Check Out, clicked Continue as Guest, chose pickup, entered the store ZIP and applied it. Success required the ZIP editor to close and store results to load. The test then independently inspected each browser's applied ZIP and result IDs, proving that the second monitor did not reuse the first monitor's Dallas results. Repeating the first monitor reopened its existing browser without adding another item or restarting checkout.

No store radio, Continue to Pickup Details, contact, payment or order submission was clicked by the flow. Apple's own default selection is left for the user to review.

The implementation also handles a post-add page without Review Bag by checking the cart once, with no repeated Add submission. Product family, color, capacity, exact cart SKU and quantity are checked. Duo is still not available for a live add test.

Offline JavaScript tests cover the limited button whitelist, one-time checkout/guest/Apply actions, exact ZIP entry and waiting for completed search results. The Rust policy forces the old global auto-open setting off, including configurations that previously enabled it.
